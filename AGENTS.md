# Project rules
Work in this existing checkout; do not create repositories or worktrees unless asked. Read README.md, docs/DECISIONS.md and research/evidence_gaps.md first.

Build one original, high-quality KDP colouring/activity book before expanding. Pilot: November 10–December 9, 2026; discretionary ceiling C$50–100; Amazon.com and Amazon.ca. No paid APIs, tools, hosting, subscriptions, orders, uploads, publishing, or spending without explicit approval. No FBA inventory.

Preserve research/raw sources byte-for-byte. Never overwrite user work. Separate marketplace observations, publisher/retailer facts, third-party snapshots, analyst judgments and unknowns. Record exact URLs, UTC retrieval time, source location, limitations and verification status. Blank CSV fields mean unknown, never zero. Never manufacture BSR, sales, search volume, reviews, facts or profitability. Qualitative niche scores are not sales probabilities. Retain original scores; document revisions with evidence.

Respect access restrictions; do not bypass CAPTCHA, authentication or anti-bot controls. Record failures. Use original illustrations, no copyrighted characters or copying competitor artwork. No illustrations in Milestone 0. No full production generator until blueprint approval. Verify bird anatomy, field marks, facts and regional/seasonal claims with authoritative sources before final copy. Do not present candidate species as locally universal.

64 pages means 30 art + 30 activities + 4 matter pages, printed on both sides. Never advertise single-sided or marker-bleed-proof. Generated assets require human anatomical and print-resolution review. Recheck current official KDP printing costs, royalties, margins, cover dimensions, content and AI-disclosure policy before publication. Never promise approval or monetization.

Use Python standard library first; consider Pillow, ReportLab and pypdf only when production work is approved. No unnecessary services or frameworks. Test meaningful data invariants. Run python scripts/validate_milestone.py before committing; inspect git diff and preserve unrelated edits. Keep changes reviewable. Human approval is required before assets, blueprint freeze, production implementation and release actions.
