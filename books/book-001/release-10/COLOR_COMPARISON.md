# RGB-to-CMYK cover comparison

The frozen RGB cover and original PNG remain unchanged. `cover-b1-a-cmyk-release-candidate.pdf` is a **provisional review candidate**, not an approved print color or KDP-certified file. See `rgb-vs-cmyk-front-comparison.pdf` for original-size front covers and `rgb-vs-cmyk-screen.png` for the same screen comparison. The images show the same composition and typography; the CMYK simulation renders the greens darker and the cardinal red less orange/more magenta. Screen appearance varies by viewer and is not a soft proof of a specific press.

The source scene in the frozen full wrap is 4408 × 3612 pixels, placed at 8.5 × 6.9608 in. It was converted at that native output size without interpolation, then embedded losslessly in `/DeviceCMYK`; vector RGB fill colors were converted separately and all type and shapes remain vector. Pure white/black are kept as process white and K-only black. Output sampling is approximately **518.6 × 518.9 PPI**. The preserved pre-upscaling scene was 1102 × 903, about **129.7 PPI** at that placement. The AI-created extra pixels are not original detail.

Method: Pillow/ImageCms LittleCMS, relative-colorimetric intent, Artifex Ghostscript sRGB source profile `default_rgb.icc` (SHA-256 `eddaf344b5edea13269e0d20055f335610e5e0b6e33e6e536f2701bc18c5f7d5`) to Artifex CMYK SWOP `default_cmyk.icc` (SHA-256 `8472fa1493a024b800b67dee9424835ec0c41ab79490200ae8ec4a689fd1b9a9`). The profiles are used for conversion and are not embedded in the output. SWOP is a local *assumption*, not a profile specified or validated by KDP; do not assume it matches KDP's actual press. The [KDP cover guidance](https://kdp.amazon.com/en_US/help/topic/G201953020), checked 17 November 2026, recommends CMYK images and says embedded profiles are removed. The downloaded template readme requests a CMYK profile, so confirmation of the intended handling is still needed.

A 551 × 452 pixel box-sampled version of the scene was transformed RGB → SWOP CMYK → RGB through the same profiles for a diagnostic, with average absolute channel difference **11.0 / 255** and 95th percentile of the largest per-pixel channel change **56 / 255**. This is an uncalibrated numerical comparison, not ΔE, print accuracy or a pass/fail threshold. Sampling every eighth pixel in the CMYK scene found total channel coverage near **298% maximum**; the actual KDP ink limit and print condition are not established, so this is not a compliance result. Metrics and the six converted vector fill colors are in `color-measurements.json`.

An initial Ghostscript pdfwrite color conversion encountered an interpreter error and was not used. The source PDF also contained oversized font character-map blocks; splitting these blocks without changing their mappings made both final candidates readable by Ghostscript's null renderer. The final conversion instead uses LittleCMS for the scene and six known solid RGB colors, then retains the original vector geometry and embedded fonts. Automated tests compare text, text bounds, dimensions, image placement, barcode clearance and original source hashes. A color-managed human review, confirmation of the printer condition, eventual KDP Previewer and a physical proof remain necessary.
